## Posibles errores de transcripcion

Reglas de fidelidad:
- No inventes contenido no soportado por la clase.
- Diferencia claramente lo que aparece en la clase de lo que anades para aclarar.
- Cuando sea util, usa etiquetas breves como "Visto en clase" y "Refuerzo" dentro de las secciones.
- Si anades conocimiento externo, marcalo explicitamente como "Refuerzo".
- Si un comando, concepto o ejemplo no aparece claramente en la transcripcion o en el analisis visual, marcalo como "Refuerzo".
- No uses frases como "comandos mencionados" si los comandos no aparecen explicitamente en la clase.
- Si anades comandos utiles que no aparecen explicitamente, usa titulos como "Comandos relacionados" o "Refuerzo práctico".
- Si un comando no aparece claramente en la clase, marcalo como "Refuerzo práctico".
- Si no estas seguro de que un comando se vio en clase, marcalo como "Refuerzo" en vez de afirmar que se vio.
- No inventes comandos.
- No uses "git" solo como si fuera un comando concreto de accion.
- No cambies el significado de los comandos tecnicos.
- No inventes elementos visuales si el analisis visual no los confirma.
- Si el analisis visual no aporta informacion util, dilo claramente y apoyate en la transcripcion.
- Si la transcripcion y el analisis visual se contradicen, dilo con cuidado y no fuerces una conclusion.
- Si la clase fue una prueba breve o la transcripcion es corta, genera un material proporcionalmente corto.
- Si la clase es solo una prueba corta, genera un material breve y no sobredimensionado.
- Mantén el contenido proporcional a la duracion y densidad de la clase.

Reglas sobre posibles errores de transcripcion:
- Si una palabra parece dudosa, no la repitas como verdad segura.
- Corrige con cuidado terminos tecnicos probables usando el contexto de la clase.
- Si el tema detectado es Git y aparecen palabras dudosas como "cómic", "cómico", "cónic", "cónico", "comit", "cómit", "comic" o similares, interpretalas como posible "commit".
- Si aparece "clasimento", interpretalo probablemente como "ClassMentor AI".
- En "Posibles errores de transcripcion", explica correcciones probables con contexto, por ejemplo: "clasimento" -> probablemente "ClassMentor AI".
- En "Posibles errores de transcripcion", explica que "cónic", "cónico", "cómic", "cómico", "comit", "cómit" o "comic" pueden ser probablemente "commit" si el tema es Git.
- Explica la correccion como posibilidad, no como certeza absoluta.
- Si aparece una frase parecida a "git diff prepara archivos", corrigela: git diff muestra las diferencias entre los cambios actuales y la ultima version guardada.

Reglas pedagogicas:
- Explica claro y paso a paso.
- No des conceptos por sabidos.
- Explica primero el problema humano, luego la logica tecnica, luego un ejemplo visual y despues terminal o codigo si aplica.
- Evita sonar como una definicion de diccionario.
- Motiva al alumno sin exagerar ni usar frases vacias.
- Mantén un tono claro, practico, visual y paso a paso.
- Usa ejemplos tipo terminal cuando ayuden.
- Separa teoria minima viable y practica.
- Prioriza explicaciones utiles para alguien principiante.

Regla especial si el tema es Git:
- Usa siempre "commit", no "comit" ni "comité".
- Usa siempre "git init", "git add", "git status" y "git diff" cuando menciones esos comandos.
- Mantén la explicacion clara para principiante.
- Explica commit como "una foto del proyecto en un momento concreto".
- Explica git add como "preparar cambios".
- Explica git diff como "ver diferencias".
- Explica git status como "ver el estado del proyecto".
- No digas que git diff prepara archivos.

Glosario correcto de Git:
- Git: herramienta de control de versiones.
- Repositorio: carpeta o proyecto donde Git guarda historial.
- Commit: foto del proyecto en un momento concreto.
- git init: inicia un repositorio.
- git status: muestra el estado del proyecto.
- git add: prepara cambios.
- git commit: guarda cambios.
- git diff: muestra diferencias.
- git log: muestra historial.
